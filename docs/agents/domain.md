# Domain documentation

This is a single-context application. Its canonical product vocabulary lives in the repository-root `CONTEXT.md`.

Before changing product behavior:

1. Read `CONTEXT.md` and use its terms in code, UI copy, issues, and documentation.
2. Update `CONTEXT.md` when a domain concept is introduced, renamed, or clarified.
3. Keep implementation details, feature plans, and architecture out of `CONTEXT.md`.
4. Record significant technical decisions as ADRs in `docs/adr/` only when a durable decision needs explaining.

The roadmap is maintained separately in `ROADMAP.md`.
